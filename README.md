# PCTO Service Training Hub (static site)

Volunteer training portal for Power Chapel The Oasis, Louisville GA. A single `index.html` (HTML + CSS + JS, no framework, no build step needed to run it) using Firebase Auth + Firestore, hosted on GitHub Pages.

## Safety notice

Module content is provisional and not independently verified against the final approved checklist. Electrical/breaker instructions (Facility module) are safety-sensitive, only authorized personnel should perform them, and need local policy review before production use.

## Roles

| Role | Can do |
|------|--------|
| guest (not signed in) | Browse every module. Nothing is saved. Needs no Firebase. |
| user | Do own assigned modules, take quizzes, submit for approval. |
| lead | Everything a user can, plus review/approve team submissions and assign modules. |
| admin | Everything a lead can, plus change roles, activate/deactivate users, send password-reset emails. |

People create their own account on the sign-in page (always role `user`). Admins manage roles afterwards. A static site cannot create other people's Auth accounts without signing the admin out, so there is no "create user" button by design.

## Firebase setup (step by step)

1. Go to https://console.firebase.google.com and click **Add project** (Analytics not needed). The free Spark plan is enough.
2. **Build > Authentication > Get started > Sign-in method**: enable **Email/Password**.
3. **Build > Firestore Database > Create database**: choose production mode and a region near you.
4. **Firestore > Rules**: paste the entire contents of `firestore.rules` and **Publish**. Then open the **Rules Playground** and test it (see below).
5. **Authentication > Settings > Authorized domains > Add domain**: add `USERNAME.github.io` (your GitHub username). `localhost` is already allowed for local testing.
6. **Project settings (gear) > Your apps > Web (</>)**: register an app, copy the config object, and paste the values into `const firebaseConfig = {...}` near the top of the script in `index.html`. (Firebase web config values are identifiers, not secrets; security comes from the rules.) Leave `storageBucket:''`.
7. **GitHub Pages**: push these files to a repo, then **Settings > Pages > Build and deployment > Source: Deploy from a branch > main / (root)**. The site appears at `https://USERNAME.github.io/REPO/`.
8. **Promote the first admin manually**: sign up in the app, then in the Firebase console open **Firestore > users > (your document) ** and change the field `role` from `user` to `admin`. Reload the app. After that, admins can promote others from **Manage Users**. (The rules deliberately forbid anyone from making themselves admin.)

### Test the rules (Rules Playground)
In Firestore > Rules > **Rules Playground**, simulate as authenticated users with real uids and check at least: user reads own `users` doc (allow) and another user's (deny); user updates own `role` (deny); user writes own `progress` doc with `approvedAt` set (deny); lead updates someone else's progress `approvedBy`/`approvedAt` (allow); lead updates own (deny); inactive user reads anything but own `users` doc (deny); only admin reads `audits`. Create the needed `users` docs first so the `get()` role lookups resolve.

## Editing workflow (no installs)

Open the repo on github.com and press `.` (or visit `vscode.dev/github/USERNAME/REPO`) to edit in the browser, then commit; GitHub Pages redeploys in about a minute. `index.html` is generated by `build.py` from `src/` plus the original app files, but you can also edit `index.html` directly. If you rerun `python3 build.py [path-to-original-folder]` it regenerates `index.html` and you must re-paste your Firebase config afterwards (or edit the placeholder in `src/js1.js`).

## CDN / HTTPS

Firebase is loaded from `https://www.gstatic.com/firebasejs/10.14.1/...` with `<script type="module">`. Every URL must be `https://` (GitHub Pages is HTTPS; `http://` CDN links are blocked as mixed content). Firebase loads only when the config has been filled in, so Guest mode works even before setup.

## Data model

- `users/{uid}`: name, email, role (`user|lead|admin`), active, created
- `assignments/{uid_moduleId}`: uid, moduleId, assignedBy, assignedAt
- `progress/{uid_moduleId}`: uid, moduleId, completed (task indexes), quizPassed, quizAttempts, submitted, approvedBy, approvedAt, notes
- `audits/{autoId}`: actor, action, target, created

## Limitations (please read)

- **Quiz answer key is in the page source.** This is a static site, so anyone can read it. Quizzes are low-stakes learning checks; **approval by a lead is the real gate.** The rules cannot verify quiz results.
- **Photo notes are stored locally only** (IndexedDB in the browser on that device). They are never uploaded: Firestore documents are limited to 1 MB and Firebase Storage needs a paid plan. They are not synced across devices, not visible to leads, and are lost if browser data is cleared.
- Notes typed in the notes box (text) are saved to Firestore with your progress.
- Deactivating a user blocks data access via the rules and signs them out of the app, but does not delete their Auth account (do that in the console).
- Leads cannot approve their own submissions (enforced in rules); another lead or an admin must.
- Rules and UI were written without being run against a live Firebase project; test them in the Rules Playground and with a throwaway account before real use.
- Module content is provisional (see Safety notice). No user data, credentials, or real people's information belongs in this repository.
